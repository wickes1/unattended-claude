## F01 Happy session-id discovery via /status

**Background:** Happy 1.1.8 swallows `--session-id` in hook mode (the only mode), but `/status` slash command in claude TUI shows `Session ID: <uuid>` (verified via user screenshot 2026-05-23). This is the user-facing contract and works regardless of `bin=claude` vs `bin=happy`. We use it as the sole mechanism — no filesystem-layout fallback needed.

**Files:**
- Modify: `src/runtime/claude-session.ts` (buildLaunchCommand, ClaudeSession.run)
- Modify: `src/types.ts` (verify TaskRuntimeState.claude_session_id)
- Create: `src/runtime/session-discovery.ts` (discoverViaStatus)
- Test: `tests/runtime/session-discovery.test.ts`
- Test: `tests/runtime/claude-session-happy-mode.test.ts`

**Spec:**
1. `buildLaunchCommand(opts, mode)` where mode = first-launch | resume:
   - bin=claude, first-launch → `claude --session-id <uuid> <extra_args>` (pre-gen still works for claude bin)
   - bin=claude, resume → `claude --resume <uuid> <extra_args>`
   - bin=happy, first-launch → `happy <extra_args>` (NO --session-id, Happy ignores it)
   - bin=happy, resume → `happy --resume <uuid> <extra_args>` (Happy forwards this)
2. `discoverViaStatus(zellijOps, parent, tab, clock, timeoutMs=10000)`:
   - After TUI prompt is ready: sendText `/status\n`
   - Wait 1s for panel to render
   - capturePane (large window) and parse `/Session ID:\s+([0-9a-f-]{36})/i`
   - sendKeys `Esc` to dismiss panel
   - Throws if not found after timeoutMs
3. After first-launch in happy mode (or any mode where buildLaunchCommand didn't pre-gen), call discoverViaStatus and stash UUID on TaskRuntimeState.claude_session_id. Subsequent episodes use --resume.
4. For bin=claude with pre-gen, can skip discoverViaStatus entirely (we already know the UUID).

**Tests:**
- discoverViaStatus happy-path: fake capturePane returns text containing "Session ID: 4765a36e-...uuid", returns UUID
- discoverViaStatus parse failure: capturePane returns text without UUID after timeout → throws
- happy-mode first launch args: NO --session-id present in command
- happy-mode resume args: --resume <uuid> present
- claude-mode first launch: --session-id <uuid> present (regression)
- claude-mode resume: --resume <uuid> present (regression)

## F02 HANDOFF.md write + read

**Files:**
- Modify: `src/runtime/claude-session.ts` (pollUntilDone context-full path)
- Modify: `src/orchestrator/episode.ts` (applyResult context_full path)
- Modify: `src/commands/run.ts` (buildPromptFile)
- Modify: `src/types.ts` (Event variant `handoff_written`)
- Test: `tests/runtime/handoff.test.ts`

**Spec:**
1. When pollUntilDone detects context-full (regex match):
   - Inject prompt: `"Before context resets, write a concise HANDOFF.md to {handoffPath} summarising current state, completed steps, what comes next, and any open decisions. Use markdown. After writing, reply READY."`
   - Wait up to 120s for either: file exists at handoffPath OR "READY" sentinel in transcript
   - If file exists: emit `handoff_written` event, return `{ kind: "context_full", handoffPath }`
   - If timeout: emit warning, return `{ kind: "context_full", handoffPath: null }` (degraded mode)
2. applyResult context_full → record handoffPath on TaskRuntimeState
3. buildPromptFile on next episode: if TaskRuntimeState.handoffPath exists, prompt body = `"Continuing task ${taskId}. Read your prior handoff below and resume work.\n\n--- HANDOFF.md ---\n${handoffContents}\n--- END ---"` instead of original task doc

**Tests:**
- write path: mock zellij capture returns "READY" after fake-fs writes handoff → result.handoffPath set
- write timeout: no READY, no file → returns null path + warning logged
- read path: handoffPath exists in state → buildPromptFile output references HANDOFF.md contents
- read fallback: handoffPath null → buildPromptFile uses original task doc
